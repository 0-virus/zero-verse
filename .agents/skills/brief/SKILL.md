# ZeroVerse brief

이 절차는 주 에이전트가 직접 수행한다. 하위 에이전트를 만들거나 파일을 수정하지 않는다.

## 입력

인자가 없으면 backend, frontend, qa, pm 전부를 본다. 인자가 있으면 지정 역할만 본다.

## 절차

1. git branch --show-current, git status --short, git log --oneline -10으로 저장소 현실을 잡는다.
2. 대상 역할의 .claude/team/{역할}/CLAUDE.md, STATE.md, 최근 WORKLOG.md를 읽는다.
3. 전원 브리핑이면 헌법, JOURNAL, 현재 마일스톤 worklog, 결정·위험 레지스터, PRD §9·§10을 읽는다.
4. 각 역할마다 바로 시작할 일, 차단 요인과 해소 주체, STATE와 실제 Git의 차이, 다른 역할에서 받을 것, 우선순위 하나를 판정한다.
5. 역할 간 의존 사슬과 계약 모순을 찾는다. 사용자 결정과 리더/기술 결정을 구분한다.
6. 선택지를 늘어놓지 않고 다음 한 걸음 하나를 근거와 함께 권고한다.

## 검증

- STATE와 commit 메시지는 주장일 뿐이다. 실제 파일·worklog 본문·PR 상태를 확인한다.
- worklog 헤더 존재만으로 완료를 판정하지 않는다. [머지]에 실제 기록이 있는지 읽는다.
- 수치·테스트 수는 명령으로 직접 세고 분모 없는 백분율을 쓰지 않는다.
- FR/NFR·PRD §9·ADR·위험 식별자가 실제 정본에 존재하는지 검색한다.
- 미커밋 변경은 진행 중으로 표시하고 사용자 작업을 변경하지 않는다.
- 깊은 코드 조사나 역할 판단이 필요하면 브리핑 범위를 넘었다고 알리고 별도 팀 작업을 제안한다.

## 출력

- 현재 위치와 근거
- 역할별 상태·차단·의존
- 정본/STATE/Git 간 모순
- 사용자만 풀 수 있는 결정
- 최우선 다음 행동 하나
- 실행한 검증 명령과 핵심 출력
