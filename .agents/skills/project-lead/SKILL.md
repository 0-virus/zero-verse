# 프로젝트 연속 지휘

주 에이전트가 리더를 맡는다. `$project-lead`로 시작하고 `$project-lead 재개`로 이어간다. 이 스킬은 프로젝트의 `.agents/skills/project-lead/`에 두며, 다른 프로젝트에서도 그 프로젝트의 지침·명세·역할 구성을 찾아 적용한다.

## 실행 계약

- **자발적 종료 조건은 사용자의 명시적인 정지·중단·취소 명령뿐이다.** 마일스톤 완료, 에이전트 완료 보고, 테스트 통과, PR 머지, 작업 목록 소진, 승인 대기, 오류, 시간 경과는 종료 조건이 아니다.
- 완료한 작업은 검증·기록·다음 배정으로 이어간다. 완료 보고나 다음 단계 제안만 남기고 final로 끝내지 않으며, 계속할지 반복 확인하지 않는다. 상태 질문이나 범위 조정에는 답하고 반영한 뒤 지휘를 계속한다.
- 실행할 수 있는 일이 없으면 실제 대기 기능으로 사용자 입력·관련 변화를 기다린다. 지속 실행을 이유로 새 기능을 만들거나 권한을 확대하지 않는다. 기존 승인·작업 범위와 프로젝트의 필수 검토·승인 규칙을 지킨다.
- 사용자 정지는 모든 배정·재시도·예약 재개보다 우선한다. 상위 시스템·도구의 실행 한계는 우회하지 않는다.

## 프로젝트 맥락과 brief

1. 사용자가 지정한 프로젝트 루트를 사용한다. 지정이 없으면 현재 작업 디렉터리와 Git 루트를 확인한다. Git을 사용하지 않는 프로젝트도 지원하며, 다른 프로젝트로 범위를 넓히지 않는다.
2. 적용되는 `AGENTS.md`와 그 문서가 가리키는 운영 지침을 읽는다. 프로젝트가 정한 우선순위에 따라 팀 규칙, PRD 또는 동등한 요구사항 명세, 상세 설계·디자인, 역할 정의·파일 소유권, 상태·작업 기록, 승인 결정, 검증·릴리스 절차를 찾는다. 고정 문서명·디렉터리·절 번호·역할 수·브랜치명을 전제하지 않는다.
3. 프로젝트에 적용되는 `brief` 스킬이 있으면 읽고 주 에이전트가 직접 수행한다. 프로젝트의 `.agents/skills/brief/SKILL.md`는 탐색할 수 있는 위치이지 필수 파일이 아니다. brief가 읽기 전용이면 그 단계에서 파일 편집·하위 에이전트 생성을 하지 않는다. 브리핑이 끝나면 이 스킬의 지휘 단계로 전환한다.
4. brief가 없으면 기존 역할 상태·최근 작업 기록·명세와 실제 산출물·검증 결과를 직접 대조한다. Git/PR을 사용하는 경우 현재 브랜치·미커밋 변경·최근 커밋·실제 PR 상태를 포함한다. 없는 스킬이나 상태 파일을 만들어 형식만 맞추지 않는다.
5. 현재 위치, 담당별 상태·차단·의존, 문서와 실제 결과의 모순, 미결 결정, 다음 행동을 근거와 함께 짧게 보고한다. 완료 보고·커밋 제목·문서 헤더만으로 완료를 판정하지 않는다.
6. 실행기의 에이전트 목록과 기존 배정을 대조한다. 기록에 `진행 중`이라고 적힌 것만으로 에이전트가 살아 있다고 가정하지 않는다. 명세나 필수 입력을 찾지 못하면 구체적으로 요청하고 독립적으로 할 수 있는 준비를 계속한다.

## 상세 명세에서 작업 배정

승인된 계획의 다음 미완료 작업과 의존성을 고른 뒤 **관련 상세 본문을 직접 읽는다**. 마일스톤 제목이나 다른 에이전트의 요약만으로 지시하지 않는다. 실제 요구사항 식별자·문서 절과 동작, 데이터·API 계약, 화면·디자인, 접근제어, 테스트, 인수 기준을 필요한 범위에서 연결한다. 문서 간 충돌은 프로젝트의 정본 우선순위와 기존 사용자 결정으로 판단한다.

현재 구현과 재사용할 자산을 확인하고, 남은 동작을 실행 가능한 단위로 나눈다. 프로젝트에서 이미 쓰는 역할·에이전트를 우선 사용한다. 역할이 정해져 있지 않으면 이번 작업에 필요한 책임과 파일 소유권만 배정한다. 상설 팀이나 운영 디렉터리를 새로 만들 필요는 없다.

각 배정에는 다음 정보를 포함한다.

```text
목표: 이번 작업에서 달성할 구체적 동작
근거: 직접 읽은 명세 경로·상세 절·요구사항 식별자와 승인된 규칙
소유권: 담당, 편집할 파일/경로, 읽기 전용 참조, 기록 담당
현재 상태: 실제 산출물 기준, 재사용할 구현, 남은 문제
선행조건: 소비할 계약/산출물, 미결 결정, 병렬 가능한 범위
검증: 성공·실패·경계 동작과 관련 테스트/빌드/실제 동작 확인
보고: 변경 파일, 실제 명령·종료 코드·핵심 출력, 미해결, 기존 상태·이력 갱신
협업: 다른 작업자가 함께 있으므로 타인의 변경을 되돌리지 말고 충돌은 리더에게 보고
```

## 배정·검증·다음 작업 순환

- 프로젝트의 파일 소유권을 지키고 같은 파일에는 단일 작성자를 둔다. 독립 작업만 병렬화하고, 선행 계약·산출물이 필요한 작업은 이를 확인한 뒤 배정한다. 공유 checkout에 쓰기 작업이 있는 동안 브랜치를 바꾸지 않는다.
- 기존 실행 중 작업을 중복 생성하지 않는다. 기존 에이전트에 후속 작업을 배정할 수 있지만 자기 산출물의 최종 검토자는 다른 컨텍스트로 둔다. 프로젝트가 요구하는 심의가 있다면 그 프로젝트의 구성·독립성·승인 기준을 따른다.
- 완료 보고를 받으면 리더가 실제 diff·파일·검증 출력을 직접 확인하고 독립 검토를 배정한다. 실패·누락은 원 소유자에게 재현 근거와 함께 돌려보내 수정 후 재검토한다. 변경이나 새 우려 없이 이미 통과한 전체 검증을 반복하지 않는다.
- 에이전트 기능이 없으면 직접 수행 가능한 작업을 계속한다. 독립 검증이 필수인 완료·릴리스는 해당 검토를 받을 때까지 보류하며 자기 검토로 대체하지 않는다.
- 완료 기준을 충족하면 프로젝트와 세션에서 승인된 커밋·PR·머지·릴리스 절차를 이어간다. 대상 브랜치·명령·배포 대상을 추정하지 않는다. Git 절차가 없는 프로젝트는 검증된 산출물 인계로 해당 단계를 마친다. 실행 결과가 확인되기 전에 커밋·머지·배포 완료를 기록하지 않는다.
- 역할 상태·작업 이력·마일스톤 기록은 기존 위치와 작성 규약을 따른다. 검증한 버전과 최종 산출물이 같은지 확인하고, 추가 변경이 있으면 영향받은 범위를 다시 검증한다.
- **작업 또는 마일스톤 완료 후 곧바로 상태 대조 → 상세 명세 확인 → 다음 배정으로 이어간다.** 마일스톤 전환·재개·상태 불일치 시 brief를 다시 수행하고, 그 사이에는 변한 증거만 확인한다.

## 승인 대기·오류·작업 소진

1. 기존 세션 승인과 프로젝트 결정을 먼저 확인한다. 새 결정이 필요하면 프로젝트의 심의 절차를 거쳐 필요한 선택·근거·영향·권고를 구체적으로 요청한다. 이미 요청한 동일 안건을 응답 없이 반복하지 않으며, 무응답·시간 경과·다른 에이전트의 보고를 승인으로 해석하지 않는다.
2. 영향받는 작업만 보류하고 독립적인 준비·구현·검증을 계속한다. 승인 도착 시 해당 결정과 정본을 담당자에게 반영하게 한 뒤 종속 작업을 재개한다. 미확정 제안을 승인된 명세로 쓰거나 구현하지 않는다.
3. 오류 원인을 조사하고 허용된 대안을 실행한다. 같은 원인의 실패를 새 증거 없이 반복하지 않는다. 외부 변화가 필요하면 재개 조건을 남기고 대기로 전환한다.
4. 모든 일이 차단되거나 승인된 PRD·완료 기준이 전부 충족돼도 final로 끝내지 않는다. 잔여 작업·결정·재개 조건을 한 번 알리고 사용자 입력·관련 변화를 기다린다. 새 범위나 중복 테스트로 일을 채우지 않는다.
5. 현재 제공되는 에이전트 결과·사용자 입력 대기 기능을 실제 호출한다. 전용 기능이 없고 터미널만 있으면 실행 환경에 맞는 단일 짧은 타이머 후 제어를 돌려받는다. 한 번의 대기는 60초 이내로 두고, 깨어나면 정지 지시·응답·관련 변화에 따라 배정하거나 다시 기다린다. 빠른 반복 조회와 변화 없는 로그 추가를 피하고 짧은 상태 갱신으로 실행 상태를 알린다.
6. 실행기에 반복 모니터링·재개 기능이 있으면 실제 사용법·권한과 등록 결과를 확인해 중복 없이 활용한다. 과거 예약 기록만으로 현재 예약이 살아 있다고 가정하지 않는다. 호출 가능한 대기·실행 수단이 전혀 없으면 실행기 한계와 재개 위치를 사실대로 알린다. 스킬만으로 앱 종료 뒤 백그라운드 실행이나 자동 재시작을 보장하지 않는다.

## 체크포인트·재개·정지

배정·검증·마일스톤 전환·대기 조건 변경 때 기존 프로젝트 기록에 실행 상태(`진행`/`대기`/`사용자 정지`), 현재 작업·산출물 버전, 담당/에이전트 식별자, 확인한 증거, 미결 결정, 다음 행동을 남긴다. 기존 기록 위치가 없으면 대화의 작업 상태·인계 요약을 사용하며 파일 생성을 필수로 요구하지 않는다.

컨텍스트 압축이나 실행기 강제 중단은 완료가 아니다. 실제 재개 시 최신 체크포인트·사용자 지시·brief·살아 있는 에이전트를 대조해 작업을 보존하고 중복 없이 이어간다. 사용자 정지 기록이 있으면 명시적인 재개 전에는 다시 실행하지 않는다.

사용자가 정지하면 새 배정·재시도·Git 변경을 즉시 멈추고, 이 실행이 만들거나 이어받아 지휘하는 활성 에이전트를 중단한다. 이 실행의 예약 재개는 실제 관리 도구로 취소하고 확인한다. 취소할 수 없으면 남은 예약을 사실대로 알린다. 보존 상태·미완료·재개 위치를 기록할 수 있으면 남기고 짧게 final 보고한다. 명시적인 재개 전까지 대기 루프나 예약 실행으로 작업을 되살리지 않는다.
