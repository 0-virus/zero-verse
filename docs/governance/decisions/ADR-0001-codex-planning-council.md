# ADR-0001: Codex 독립 기획 심의팀 운영

- 상태: `ACCEPTED`
- 결정일: 2026-07-24
- 결정 주체: 사용자
- 관련 회의: 없음
- 관련 마일스톤: 전체
- 대체한 ADR: 없음

## 맥락

기존 개발 프로세스는 Codex가 계획과 최종 리뷰를 담당하고 Claude가 구현을 담당한다. 중요 결정과 범위가 큰 마일스톤에서 제품 적절성, 기술 실현 가능성, 전달 위험을 구조적으로 검토하고 그 근거를 저장소에 남길 절차가 필요하다.

## 결정

기존 Claude 개발 ↔ Codex 계획·리뷰 파이프라인에 조건부 기획 심의를 추가한다.

심의팀은 Codex 진행자 한 명과 서로 결과를 공유하지 않는 독립 검토 에이전트 세 명으로 구성한다. 독립 에이전트는 각각 제품성, 기술 실현성, 전달·위험을 검토한다. Codex 진행자는 결과를 종합하고 위험 등급을 판정한다.

`LOW` 결정만 규칙에 따라 자동 승인한다. `MEDIUM`, `HIGH`, `BLOCKED`는 사용자 결정 없이는 구현하지 않는다. 회의록과 결정은 `docs/governance/`의 Markdown 문서로 Git에 추적한다.

## 근거

- 기존 저자 Claude와 검토자 Codex의 역할 분리를 유지한다.
- 독립 컨텍스트 검토로 역할 간 동조를 줄인다.
- 세 전문 관점에 의무 반대 논거를 포함해 작은 실행팀 안에서 반론 기능을 확보한다.
- 제품 명세와 코드 변경이 같은 저장소에서 추적된다.

## 결과

### 긍정적 결과

- 중요한 결정의 근거, 위험, 승인 주체를 추적할 수 있다.
- 저위험 결정은 자동 승인해 사용자 병목을 제한한다.
- 구현 전후에 계획, 결정, worklog, PR의 일치 여부를 검증할 수 있다.

### 부정적 결과와 비용

- 회의 대상 판단과 문서 작성 비용이 추가된다.
- 과도한 소집은 마일스톤 진행을 늦출 수 있다.
- 위험 등급 경계가 불명확하면 사용자 승인 요청이 불필요하게 늘어날 수 있다.

## 대안

| 대안 | 채택하지 않은 이유 |
|------|---------------------|
| Notion 등 외부 문서 | 저장소의 명세·코드·결정 간 추적이 분산되고 현재 규모에 비해 운영 비용이 큼 |
| Claude와 Codex 혼합 심의팀 | 현재는 Codex 진행자와 독립 에이전트만 사용하는 단순한 구성을 우선함 |
| 모든 결정 사용자 승인 | 낮은 위험의 가역적 결정까지 병목이 됨 |
| 다수결 자동 결정 | 근거의 강도와 위험도를 반영하지 못함 |

## 검증 방법

- 각 소집 대상 회의에 세 독립 검토 결과가 모두 존재해야 한다.
- 자동 승인된 회의는 `LOW` 조건을 전부 확인해야 한다.
- 마일스톤 worklog와 PR 리뷰에서 관련 회의록·ADR 반영 여부를 확인한다.
- M0~M2 완료 후 소집 빈도, 승인 대기 시간, 재결정 횟수를 회고한다.

## 롤백 또는 대체 조건

M0~M2 회고에서 심의 비용이 이점보다 크거나 중요 위험을 반복적으로 놓친 경우 역할 수, 소집 조건 또는 승인 기준을 새 ADR로 대체한다.
