# ADR-0002: 비도메인 API 오류 코드 분류

- 상태: `ACCEPTED`
- 날짜: 2026-07-25
- 등급: `HIGH`
- 결정 주체: 사용자
- 관련 회의록: [`M0-20260725-scaffold`](../meetings/M0-20260725-scaffold.md)
- 관련 마일스톤: M0
- 관련 문서: `docs/REQUIREMENTS.md` §NFR-03~04, `docs/PRD.md` §4.1·§4.4·§9.4-W

## 맥락

`docs/REQUIREMENTS.md` NFR-03은 Bean Validation 400, 리소스 없음 404, 인증·권한 오류의 HTTP 상태 구분을 요구한다. 그러나 NFR-04의 에러 코드 목록에는 **비즈니스 도메인 prefix**(AUTH_/USER_/BLOG_/POST_/CAT_/UNI_/COM_/LIKE_/NOT_/ADMIN_/UPLOAD_)만 존재하고, 다음 세 부류에 대응하는 코드가 없다.

1. Bean Validation 위반(요청 DTO 검증 실패)
2. 매핑되지 않은 경로 등 특정 도메인에 귀속시킬 수 없는 404
3. 처리되지 않은 서버 예외(500)

M0는 `GlobalExceptionHandler`와 공통 응답 래퍼를 코드로 확정하는 마일스톤이므로(`docs/PRD.md` §10 M0, §4.1·§4.4), 이 공백을 메우지 않으면 글로벌 예외 처리 계약이 미완성으로 남는다. 초기화 이전 구현은 문서에 없는 `VALIDATION_001`, `404`, `INTERNAL_SERVER_ERROR`를 임의로 사용했다.

## 검토한 선택지

| 선택지 | 내용 | 판정 |
|--------|------|------|
| A | `VALIDATION_*` / `COMMON_*` prefix를 신설하고 NFR-04를 개정 | **채택** |
| B | 요청이 속한 도메인의 기존 prefix로 매핑 | 기각 — 미매핑 404·미처리 500은 귀속 도메인이 존재하지 않아 코드 의미가 왜곡된다 |
| C | M0에서는 `BusinessException` 계열만 확정하고 나머지 보류 | 기각 — M0에 명시된 글로벌 예외 처리 계약을 미완성으로 남긴다 |

독립 검토 3인(Product / Architecture / Delivery & Risk)이 서로 컨텍스트를 공유하지 않은 상태에서 **전원 A를 권고**했다.

## 결정

1. 비즈니스 오류는 기존 **도메인 prefix를 유지**한다.
2. 도메인에 귀속시킬 수 없는 오류는 다음으로 분류한다.

| 코드 | HTTP | 용도 |
|------|------|------|
| `VALIDATION_001` | 400 | Bean Validation 위반. 필드별 오류 상세를 응답에 포함한다. |
| `COMMON_404` | 404 | 매핑되지 않은 경로 / 도메인 특정 불가한 리소스 없음. |
| `COMMON_500` | 500 | 처리되지 않은 서버 오류. |

3. `COMMON_500` 응답에는 **고정된 외부 메시지만** 제공한다. stack trace, SQL, 내부 경로, 원본 예외 메시지를 노출하지 않으며 상세는 서버 로그에만 남긴다.
4. 위 코드는 `docs/REQUIREMENTS.md` NFR-04에 **공개 API 계약**으로 기록한다(개정 완료).
5. 공개 소비자가 생긴 뒤의 변경은 호환성 검토와 별도 기획 심의를 거친다.

## 결과

- `docs/REQUIREMENTS.md` NFR-04에 "비도메인 공통 오류 코드" 표 추가.
- `docs/PRD.md` §4.4에 요약 반영, §9.4-W에 결정 기록.
- `ErrorCode` enum에 세 코드를 포함하고, `GlobalExceptionHandlerTest`에 Validation 400 / 미매핑 404 / 미처리 500의 status·code·공통 래퍼 검증과 **500 응답의 내부 정보 비노출 검증**을 추가한다(M0 완료 조건).

## 반대 논거와 잔여 위험

- 반대 논거: 요구사항 정본 개정은 되돌리기 비용이 큰 공개 계약 변경이며, MVP 단계에서 코드 체계를 조기에 고정하면 이후 세분화 요구가 생겼을 때 호환성 부담이 남는다.
- 완화: 최소 3개 코드만 고정하고 세분화는 필요 시점에 별도 심의로 확장한다. 소비자가 없는 현재가 변경 비용이 가장 낮은 시점이다.
