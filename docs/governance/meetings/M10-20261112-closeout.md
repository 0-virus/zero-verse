## 1. 결정할 질문

공개 API·DB schema·보안/제품 정책·외부 의존성을 바꾸지 않고, 현재 소스의 fresh 전체 회귀·결정성/build-tooling 최소 수정·격리 HTTP/MySQL/Chrome 인수·독립 QA로 M10 local MVP를 마감하는 A안을 실행할 것인가?

## 2. 배경과 범위

### 배경

- PRD §10 M10은 `§11 전체 통과, §12 DoD 충족`으로 정의되나 fresh 실행·역사 evidence 재사용·실제 인수 범위가 한 줄에 명시되지 않았다.
- M0~M9는 각각 완료됐지만 source와 테스트가 누적 변경됐으므로 과거 PASS를 현재 통합 source PASS로 합산할 수 없다.
- 2026-11-12 fresh frontend baseline은 51 files/465 tests·lint/build PASS다. backend full baseline은 637 tests 중 조회수 24시간 경계 1건이 실패했고 동일 focused test는 PASS했다.
- tracked `gradlew`는 mode 100644와 비표준 `getopt` 때문에 표준 실행이 결정적으로 실패한다. wrapper JAR 직접 실행은 가능하다.
- frontend는 NFR-09의 글쓰기/수정 폼 유효성 대비 빈 발행 제목/본문 client 차단·회귀가 없고, Modal/DraftPicker의 실제 keyboard focus/Escape evidence도 없다. server는 draft empty를 허용하고 publish만 title/text-or-image를 요구한다.

### 포함 범위

- NFR-09/PRD §11 전체 coverage mapping, current source fresh BE/FE 회귀와 build.
- 테스트 결정성, build-tooling, 명시된 FE 발행 폼 유효성의 최소 TDD 수정.
- 격리 synthetic DB/runtime의 HTTP/MySQL/Chrome 1440px 실제 인수, OpenAPI/security/DoD 감사.
- 독립 whole-branch QA, 수정 loop, source/JAR/evidence provenance, PR/`dev` 통합.

### 제외 범위

- 공개 API/DB schema/인증·권한·개인정보·제품 정책/디자인 정본 변경.
- 새 외부 dependency/service/infra, S3 전환과 U0 해소, 배포, 실사용 DB·기존 업로드 적용, 운영 ADMIN bootstrap, 모바일·운영 SLA.

### 제약

- 기존 스택과 Gradle 8.10을 유지하고 사용자 데이터에 접근하지 않는다.
- 실제 계약 결함이 발견되면 해당 수정만 보류하고 별도 governance 등급·사용자 결정을 적용한다.
- 역사 evidence는 current source/JAR과 동일성이 증명되지 않는 한 fresh 실행을 대체하지 않는다.
- 저자와 독립 QA/최종 검토자를 분리하고 실패·NOT RUN·warning을 숨기지 않는다.

## 6. Codex 진행자 종합

### 합의점

- 세 검토자 모두 A안을 `APPROVE_WITH_CHANGES`로 지지했다.
- 현재 source의 fresh full gate와 actual acceptance가 필요하며 과거 수치 합산은 금지한다.
- fixed Clock은 test context로 격리하고 제품 24시간 정책은 바꾸지 않는다.
- Gradle 8.10 wrapper script/mode만 표준 복원하고 JAR/properties/version/dependency는 유지한다.
- PostEditor는 draft와 publish, text와 image-only 경계를 서버 계약과 동일하게 TDD한다.
- 최종 수정 뒤 source manifest/JAR를 고정하고 actual evidence를 새로 생성한다. 계약 변경 필요 시 해당 작업을 멈춘다.

### 이견

- Product는 A안 자체를 LOW로 보았고 Architecture·Delivery는 전체 증거 수집/전달 비용을 이유로 MEDIUM을 제안했다. Architecture는 계약 불변 실행 자체는 LOW라고 명시했다.
- focus-trap은 명시 제품 계약이 아니므로 hard blocker로 새로 만들지 않는다. 실제 keyboard 관찰과 기존 동작 회귀만 evidence로 남긴다.

### 확인된 사실

- M10은 fresh evidence와 독립 QA 없이는 아직 NOT RUN/PREPARING이다.
- frontend baseline은 PASS, backend full baseline은 1 flaky boundary failure, focused rerun은 PASS다.
- build wrapper 표준 진입점은 현재 실패하지만 wrapper JAR과 Docker runtime은 동작한다.

### 미확인 가정

- 고정 Clock으로 테스트만 결정화하면 product 24시간 정책 변경 없이 full gate가 안정적으로 통과한다.
- 실제 인수에서 새 공개 계약·schema·보안 결함이 발견되지 않는다.
- M10 전용 Docker/Chrome/DB runtime을 사용자 DB·기존 업로드와 분리해 끝까지 재현할 수 있다.

### 권고안

- A안을 필수 보완과 함께 실행한다.
- wrapper provenance·표준 옵션 smoke를 full gate보다 먼저 수행한다.
- fixed Clock은 `PostConcurrencyTest` context에만 격리한다.
- PostEditor는 `empty draft 허용`, `empty title/body publish 차단`, `image-only publish 허용`, `trim/title<=200`을 서버와 같은 카피로 검증한다.
- 제품 screenshot 최소 13장(Main, Blog, Post Detail, Editor, Auth, Setup, Settings Basic/Universe/Posts, Search, Notifications, Admin List/Detail)을 actual visible DOM에서 확보한다.
- 단일 Gradle 실행자, final-fix 이후 manifest/JAR 확정, static false-positive 수동 분류, runtime 불능 시 NOT RUN을 적용한다.

### 위험 등급

- 등급: `MEDIUM`
- 판정 근거: A 자체의 결함 수정은 계약·schema·보안·의존성 불변이고 가역적이어서 LOW 성격이나, BE/FE/QA/HTTP/MySQL/Chrome/13화면/PR 통합까지의 전달 비용과 provenance 위험이 유의미하다.
- 자동 승인 조건 충족 여부: MEDIUM이므로 자동 승인하지 않는다. 사용자의 직전 명시 지시로 승인 여부를 판정한다.
