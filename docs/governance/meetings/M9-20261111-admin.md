## 5. A-v1 제안 계약 — 전부 권고(미확정)

### 5.1 조회·데이터

- `GET /api/v1/admin/users`: `keyword`(trim, 최대100, 빈값 전체; email/nickname/name 부분검색 OR, LIKE 특수문자는 literal), optional `role=USER|ADMIN`, `status=ACTIVE|SUSPENDED`, page>=0,size1~100 default20, 고정 createdAt DESC,id DESC. 지원하지 않는 sort/enum/ID/query는 VALIDATION_001/400. FE는 디자인대로 검색 입력만, 상태/역할 select 미노출.
- data `{users:PageResponse<AdminUserSummary>, summary:{totalUsers,joinedThisWeek,suspendedUsers}}`. summary는 검색/페이지 무관·삭제 사용자 제외 전체 기준. 이번 주는 Asia/Seoul 월요일00:00 이상 요청 현재시각 이하. count/list/summary는 동일 RR snapshot.
- item은 id/email/name/nickname/role/status/profileImageUrl/createdAt/updatedAt, 기본 blog(id,title,urlSlug) nullable, blogCount/postCount. 삭제 사용자 제외, 활성 blog/post만 집계. 게시글은 draft/모든 visibility 포함. 기본 blog는 활성 blog 최소id. private 본문·비밀번호/hash/token·birthDate는 미노출. 기본 blog/통계는 batch, source LONGTEXT 로드 없음.
- `GET /api/v1/admin/users/{userId}`: 기본정보(item과 동일), blog 요약과 post 통계(total/published/draft), commentCount(본인 작성·미삭제 댓글/답글), universe 통계(outgoing/incoming ACCEPTED distinct 상대·활성 상대), connectionCount는 양쪽 ACCEPTED인 활성 상대의 distinct 수. deleted target은 USER_001/404.
- lastAccessAt은 null, 화면 `마지막 접속 기록 없음`으로 표현. 접속 수집·updatedAt 대용 금지. 가입/수정 시각은 실제 audit 사용.

### 5.2 변경·삭제

- `PUT /users/{id}/role` body `{role}`, `/status` body `{status}`; 성공 data는 canonical 상세 DTO. 현재값 반복은 성공하며 불필요 audit 변경 없음. DELETE는 empty success, actor 인증 후 이미 삭제/없는 target은 USER_001/404(재요청 포함).
- self ADMIN 회수와 self delete는 기존 ADMIN_002/400을 사용한다. self suspend도 계정 잠김 방지를 위해 같은 코드로 거부하도록 확장 제안. self ADMIN 유지·ACTIVE 유지 요청은 성공. 자기 role 전체변경 금지라는 PRD 문구와 FR의 자기 ADMIN 제거 금지 차이는 이 계약으로 명확화.
- mutation은 actor/target users를 ID 오름차순으로 잠근 뒤 current actor ACTIVE ADMIN, target 생존/상태를 재검증. JWT role만으로 허용하지 않음. 동시 상호강등/정지/삭제에서 actor 재검증으로 무권한 후행 작업을 거부. 자격 있는 actor가 남는 성공 연산만 허용.
- 사용자 soft delete는 users.deleted_at만 설정. blog/post/comment/like/universe/notification/upload/refresh row 물리·cascade 삭제 없음. 기존 ACL이 삭제 소유자의 blog/post/image 조회를 막고 댓글 placeholder 및 알림 masking을 적용하는지 독립 인수. PUBLIC 글은 SUSPENDED 상태에서 계속 공개.
- 정지·삭제 후 로그인/refresh는 기존 차단을 유지한다. FR-ADMIN-04의 새 글/댓글/좋아요/Universe 신청 및 기존 각 도메인의 ACTIVE 상태표를 회귀하며, 프로필/블로그/카테고리를 정지 계정에서 전면 금지하는 새 정책을 추가하지 않는다. User lock을 공유하는 Post/Comment/Like/Universe mutation은 먼저 lock을 얻은 작업이 commit 후 관리자 변경이 진행되거나, 관리자 변경이 먼저 lock을 얻으면 current 상태로 거부되는 경계를 검증한다. User lock을 공유하지 않는 설정 쓰기는 그와 같은 진행 중 요청의 직렬화 보장을 주장하지 않는다. 삭제 commit 이후 새 요청은 기존 생존검사에 따라 거부한다. refresh 일괄폐기는 기본안에서 제외(잠금 역전/세션정책 변경 방지).
- 삭제 안내 override 제안: `계정 접근이 차단되고 블로그와 게시글이 공개되지 않습니다. 데이터는 보존됩니다.` 확인창에 대상 email과 soft delete 효과 명시. 역할/상태 변경도 대상과 변경값을 확인 후 실행. 되돌리기 UI 없는 삭제를 복구 불가·물리 삭제로 표현하지 않음.

### 5.3 현재 관리자 인증·FE

- 모든 admin 요청은 서명/type/만료 ACCESS 검증 후 DB현재 actor를 확인. missing/invalid/wrong-type AUTH_004/401, expired AUTH_002/401, deleted USER_001/404, suspended USER_003/403, current nonADMIN ADMIN_001/403. 승격된 USER claim도 DB현재 ADMIN이면 허용, 강등된 ADMIN claim은 즉시 거부.
- 현 SecurityConfig claim ADMIN 사전거부가 승격 claim을 막으므로 admin 경로는 authenticated 이후 admin 전용 current 검증으로 교체. 다른 API 인증 계약은 변경하지 않음. 모든 성공/오류에 private,no-store.
- AdminRoute: auth loading 대기/guest signin/nonADMIN 거부 화면. DB current role을 얻는 기존 auth/me 재조회와 admin API를 사용하되 API가 최종 권한 정본. 403/USER_001 뒤 민감한 이전 목록/상세·mutation retry 폐기. transient 오류에서는 기존 입력/행을 보존하고 수동 retry.
- 계정/request/mutation 세대별 늦은 응답·클릭/retry 격리. 정렬/paging/search URL 유지, 성공 mutation 뒤 canonical 재조회, delete 성공 목록 복귀. 프로필 메뉴에 ADMIN만 관리자 링크, 전용 상단 admin 버튼/사이드바 없음.
- 1440px·radius0·크림페이퍼·정본 1100/860px. 목록 통계 3개/테이블·상세 통계/역할/상태/삭제 액션과 empty/error/loading/confirmation 포함.

## 10. A-v2 구성 보완안 — 사용자 미승인

§5를 기본으로 다음 상세를 추가하며, 충돌하면 본 절이 우선한다. 독립 3인 필수 보완을 반영한 사용자 구체 승인 대상이다.

- admin mutation은 **삭제된 행을 포함한 id 기준 scalar 또는 entity FOR UPDATE**로 actor/target IDs를 오름차순 잠근다. 앞선 인증 검사는 managed User를 올리지 않는다. 이미 managed entity가 있으면 stale state를 신뢰하지 않도록 lock 후 current 값으로 판정한다. actor 먼저/target 먼저를 역할로 정렬하지 않는다.
- target 삭제 검사보다 actor current 권한 검사를 먼저 수행한다. 존재하지 않는 target, 삭제된 target, 반복 DELETE는 USER_001/404. 자기 ADMIN 회수/정지/삭제는 ADMIN_002/400, 메시지는 `자기 자신의 관리자 권한 회수, 계정 정지 또는 삭제는 할 수 없습니다.`로 구체화 제안. self ADMIN/ACTIVE 유지 요청은 성공.
- 목록/상세 DTO에 hash/token/password/birthDate/content 본문은 없다. nullable lastAccessAt은 기록 없음이며, universe 통계는 생존 상대 ACCEPTED 방향 집계와 양방향 교집합 distinct를 사용한다. postCount는 생존 blog와 생존 post 기준, published/draft 합이 total. commentCount는 target 작성의 미삭제 댓글/답글 row 수로 한정한다.
- 목록·상세는 admin 인증 DB 조회를 포함 SELECT 14회 이하, size1→100 증가0을 검증한다. 1001명 전체 운영 SLA는 주장하지 않는다. 같은 createdAt 21개 이상/큰 offset/RR writer barrier/literal `%_\\` 검색·100자 경계·주경계/UTC변환을 검증한다.
- refresh는 기존 refresh row lock·User ACTIVE 검사 계약을 유지한다. 관리자 변경과 겹친 요청이 상태 읽기를 먼저 수행하면 응답이 늦게 도착할 수 있다. 이미 발급된 토큰과 그때 발급된 토큰도 admin API current role/status/deleted 검사를 통과해야 하며, 변경 commit 후 새 refresh는 현 상태로 실패한다. 정지 해제 후 기존 미폐기 refresh 재사용은 기존 정책을 유지한다. 전역 세션폐기를 약속하지 않는다.
- endpoint별 상태표는 구현 Task2 첫 산출물이다. 정지 사용자는 로그인/refresh 및 기존 ACTIVE 필수 동작을 거부하고 PUBLIC 읽기는 유지한다. auth/me·알림 GET read-only·프로필/설정 등 기존 승인 범위를 새로 금지하지 않는다. 삭제 사용자는 생존검사로 거부하며, User lock 비공유 설정의 진행 중 요청까지 직렬화 완료했다고 주장하지 않는다. 필요한 ACL 누락 수정이 실제 발견되면 근거·영향을 기록하고 동일 M9 보안 계약 범위로 검토한다.
- FE AdminRoute의 stale AuthUser.role만으로 서버 호출을 영구 차단하지 않는다. 인증된 계정의 진입/브라우저 복귀 시 current admin probe(기존 목록 size1 조회 재사용)를 수행하여 승격·강등·정지를 평가한다. pending 중 민감 데이터 미표시, transient 실패와 권한폐기 구분, 403/404 current actor 실패는 모든 admin cache/retry 제거. target USER_001만으로 actor session을 삭제하지 않고 target 없음으로 표시한다.
- M9 운영 bootstrap은 제품 구현/실제 DB 적용에서 제외. 합성 runtime에서만 SQL로 ADMIN 부여하고 실사용 admin 지정은 별도 운영 절차로 남긴다.

### 10.1 Architecture 결과·최종 보완

- `m9_architecture_council`: APPROVE_WITH_CHANGES / 확신도93 / HIGH. 현재 스택과 M4~M8 잠금 모델에 실현 가능. 정렬 user lock/current DB 권한, 기존 상태표, user-only soft delete/ACL, 명시 RR 목록·상세, KST/DB timezone, 오류 포함 no-store, bootstrap precondition과 malformed ACCESS 회귀가 필수다.
- 강한 반대 논거/실패: 같은 user lock을 쓰지 않는 설정까지 즉시 취소·정지 차단으로 과장하면 범위와 보장이 어긋난다. 기존 서명 유효 ACCESS의 role 누락은 JwtAuthenticationFilter에서 NPE 가능성이 있으므로 불완전 claim으로 500이 나지 않는 검증이 필요하다. 운영 bootstrap이 없으면 신규 환경에 ADMIN이 없는 것을 성공 설치로 오인할 수 있다.
- 최종 보완: 목록 **및 상세** 모든 aggregate는 명시 RR transaction. 요청시각 Clock을 한 번 읽고 KST 월요일/요청현재시각을 UTC DB audit 기준으로 변환. signed ACCESS role 누락/invalid·subject 누락/invalid 회귀는 AUTH_004/401로 안전하게 처리하며 다른 정상 인증 계약 보존.
- ACTIVE ADMIN 최소1명은 관리자 사용 precondition이며 0명인 새 DB에서 자동 승격/새 public bootstrap이 발생하지 않음을 테스트한다. 합성 runtime만 명시 SQL seed. 실사용 DB 승격은 별도 지시 없이는 하지 않는다.
- 정지·삭제/권한변경 경쟁은 profile/upload/notification user lock 공유 여부까지 표로 정리한다. refresh row→user read와 admin user lock 사이 물리 lock 관측/유한종료, 기존 Refresh 정책 불변을 실제 MySQL로 확인한다.
